Grafana es la capa de visualización del entorno: consume datos de MISP, OPNsense y Wazuh y los presenta en dashboards para el seguimiento del SOC.

| Parámetro | Valor |
| --- | --- |
| VM | `108 · grafana` |
| Redes | `prod0` + `log0` |
| IP (`prod0`) | `172.17.33.154` |
| Acceso | `http://172.17.33.154:3000/` |
| Versión probada | Grafana 12.2.0 |
| Depende de | Wazuh, MISP y OPNsense arrancados (orígenes de sus data sources; OPNsense se conecta el último — ver nota en Validación) |

## Arranque

```bash
qm start 108
qm status 108
ping -c 3 172.17.33.154
nc -zvw3 172.17.33.154 3000
```

## Validación

No basta con que la VM figure como `running` en Proxmox: estas comprobaciones confirman que el componente funciona correctamente y se comunica con el resto del entorno.

1. Abre la interfaz web y autentícate.
2. En **Connections → Data sources**, confirma que existen los data sources: `misp-alerts`, `opensense-alerts`, `wazuh-alerts`, `wazuh-authentication` y `wazuh-rest-api`.
3. Abre el dashboard principal y comprueba que todos los paneles cargan y reciben datos de su data source (los servicios origen deben estar arrancados).

<Aside type="caution" title="Paneles de OPNsense sin datos por ahora">
Los paneles que consumen `opensense-alerts` no recibirán datos hasta que OPNsense esté validado y conectado — y ese es, a propósito, el **último** paso del itinerario (ver [Siguiente paso](#siguiente-paso) más abajo). No lo interpretes como un fallo de Grafana: revisa esos paneles en concreto cuando llegues a la página de OPNsense.
</Aside>

## Configuración aplicada

### Data sources

<Aside type="note" title="Nombre literal, no errata">
El data source `opensense-alerts` se llama así ("opensense", no "opnsense") en la Grafana real de este entorno — es el nombre heredado de como se configuró originalmente, no una errata de esta página. No lo corrijas al reconstruirlo.
</Aside>

<Aside type="caution" title="wazuh-authentication lleva una contraseña embebida">
Este data source usa la contraseña de `wazuh-wui` para autenticar sus consultas contra la API de Wazuh. Si rotas esa contraseña, actualízala también aquí — ver el aviso correspondiente en [Wazuh y Velociraptor](/docs/despliegue/restauracion/wazuh-velociraptor/#credenciales).
</Aside>
